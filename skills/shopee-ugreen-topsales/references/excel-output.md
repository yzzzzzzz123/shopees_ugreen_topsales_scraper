# 四表 Excel 内容合同

唯一参考为本 Skill 的 [ugreen_topsales.xlsx](../assets/ugreen_topsales.xlsx)。只读表名、表头、布局和
类型约束，不读旧业务行作为本轮种子或结果。运行结果位置由 [worktree.md](worktree.md)
限定。模板历史行数、商品、价格和采集日期都不是本轮固定值。

## 1. 工作簿结构

必须恰有以下四表并保持顺序；标题为第 2 行，元数据为第 3–4 行，表头为第 6 行，
数据从第 7 行开始。表名、字段名及顺序不改，行数随本轮实际数据变化。

| 顺序 / Sheet | Excel 表名 | 行粒度 | 冻结位置 |
| --- | --- | --- | --- |
| 1 `商品汇总` | `ProductsTable` | 每个唯一 `(店铺ID, 商品ID)` 一行 | `F7` |
| 2 `SKU明细` | `SkuTable` | 每个商品的每个真实 model 一行 | `E7` |
| 3 `图片明细` | `ImagesTable` | 每个商品的每张主图或副图一行 | `E7` |
| 4 `抓取核验` | `AuditTable` | 每个固定核验项一行，共 17 项 | `A7` |

保留筛选表、可点击链接、合理列宽/换行、标题/元数据布局。不要沿用模板历史滚动位置。
全部外部文字为字面文本，包括以 `=` 开头的商品名称；工作簿不能含公式单元格。

## 2. 商品汇总：A:N

| 列 | 固定表头 | 类型 / 口径 |
| --- | --- | --- |
| A | 全店排名 | 整数 1…N，按本轮 Top Sales 遍历首次出现顺序；不是推算销量名次 |
| B | 列表页 | 1 起整数，本轮首次出现页；协议中的 0 起 page_index 导出时加 1 |
| C | 页内排名 | 1 起整数，首次出现页内商品卡位置 |
| D | 店铺ID | 文本 `64922227`，格式 `@` |
| E | 商品ID | 文本，来自现场 URL 身份，格式 `@` |
| F | 商品标题 | 本轮已核对身份的详情标题，不从模板回填 |
| G | 当前价格 (PHP) | 本轮列表卡展示的当前数值，非负有限数；不能冒充每个 SKU 的价格 |
| H | 月销原文 | 完整 `N Sold/Month` 原文，保留 K/M/+；确实未展示则空 |
| I | 月销下界 | 整数数值，例如 `5K+ Sold/Month` 为 5000；未展示则空 |
| J | 月销状态 | `已展示` / `未展示`；真实 `0 Sold/Month` 为已展示且下界 0 |
| K | SKU数 | 与本商品 SKU 明细真实行数相同，至少 1 |
| L | 主图链接 | 详情商品图库首张的完整 HTTPS URL，可点击 |
| M | 副图数 | 本商品图片明细中副图行数，允许真实的 0 |
| N | 商品链接 | 本轮实际详情 HTTPS URL，可点击，与商品身份绑定 |

累计 `Sold` 不等于 `Sold/Month`。价格区间、划线原价、分期金额不得无解释塞进单值列；
当前协议需明确的列表当前价格，无法明确则暂停而非猜数。

## 3. SKU 明细：A:I

| 列 | 固定表头 | 类型 / 口径 |
| --- | --- | --- |
| A | 全店排名 | 继承商品汇总 |
| B | 列表页 | 继承商品汇总 |
| C | 店铺ID | 文本，格式 `@` |
| D | 商品ID | 文本，格式 `@` |
| E | 商品标题 | 与商品汇总一致 |
| F | SKU Model ID | 纯数字文本，格式 `@`；同商品内唯一 |
| G | SKU规格 | 本轮真实 model 的非空规格映射，显示为 `规格名: 选项, …` |
| H | SKU图片链接 | 已取得真实映射时填完整 HTTPS URL；确认未提供专属图时可空 |
| I | 商品链接 | 与商品汇总一致的可点击链接 |

保留详情当前真实 model 顺序。选项笛卡尔积、导航 query 中单个 model、凭数量补行，
均不能替代完整 model 集合。不可售但仍公开的真实 model 也不能擅自漏掉。
SKU 图片未取得不等于不存在，不能将主图当作每个 SKU 的专属图补齐。本表没有 SKU
价格列，不添加未经确认的字段，也不把列表价格重复写成 SKU 价格。

## 4. 图片明细：A:I

| 列 | 固定表头 | 类型 / 口径 |
| --- | --- | --- |
| A | 全店排名 | 继承商品汇总 |
| B | 列表页 | 继承商品汇总 |
| C | 店铺ID | 文本，格式 `@` |
| D | 商品ID | 文本，格式 `@` |
| E | 商品标题 | 与商品汇总一致 |
| F | 图片类型 | `主图` 或 `副图` |
| G | 图片序号 | 主图固定 1；副图另从 1 连续编号 |
| H | 图片链接 | 完整 HTTPS 商品图 URL，可点击 |
| I | 商品链接 | 与商品汇总一致的可点击链接 |

按商品顺序排列，每个商品先主图，再按详情图库顺序排列副图。图库 URL 去重，不计
评论图、推荐商品图、视频封面、营销覆盖图。链接必须现场取得，不能猜 CDN 前缀或
删除缩略后缀来捏造原图。支持域名/路径见 [capture-protocol.md](capture-protocol.md)。
这是**图片 URL 明细合同，不要求内嵌图片缩略图**；截图、图片数量或相对路径不能替代 URL。

## 5. 抓取核验：A:C

固定表头为 `核验项`、`结果`、`说明`。以下顺序与名称严格固定：

| 顺序 | 核验项 | 通过条件 / 口径 |
| --- | --- | --- |
| 1 | 店铺 URL | PH UGREEN 当前合同范围 |
| 2 | 排序方式 | `Top Sales`，本轮已核对 |
| 3 | 列表总页数 | 本轮实际完整页数，非模板历史页数 |
| 4 | 商品卡出现次数 | 全部分页卡片数之和，包含跨页重复 |
| 5 | 跨页重复次数 | 出现次数减去唯一商品数 |
| 6 | 唯一商品数 | 去重后商品汇总行数 |
| 7 | 成功进入详情页 | 等于唯一商品数；每个身份都已现场进入并核验 |
| 8 | 详情页失败数 | 0；存在任何未解决失败不能发布 |
| 9 | 详情解析成功数 | 等于唯一商品数 |
| 10 | 详情解析错误数 | 0 |
| 11 | 未展示月销商品数 | 等于汇总中“未展示”的行数；不是月销为 0 的数量 |
| 12 | SKU 总数 | SKU 明细行数 |
| 13 | 有 SKU 的商品数 | 等于唯一商品数 |
| 14 | 主图数 | 等于唯一商品数 |
| 15 | 副图数 | 图片明细全部副图行数 |
| 16 | 无效图片 URL 数 | 0，包含已填 SKU 图、主图和副图 |
| 17 | 完整性结论 | 全部条件符合才为 `通过` |

计数、排名和审计由确定性发布脚本从输入重新生成，Agent 不提交预填“通过”的 audit。
结构校验无法自行证明网页已被完整读取，宿主仍须完成任务书的现场覆盖检查。

## 6. 元数据与最终一致性

商品汇总显示本轮上海采集时间、商品/SKU/主图/副图数、店铺来源及 Top Sales；SKU 表
显示记录数、商品数和“商品当前价格见商品汇总”的说明；图片表显示图片记录/主图/
副图数及图库顺序说明；核验表显示状态和“UGREEN Top Sales 全部分页与全部详情页”范围。

所有三张明细表按 `(shop_id,item_id)` 对齐；排名连续、标题/链接一致。ID 不能变成
科学计数或数值类型。发布先校验临时候选，再独立重开校验，全部通过才原子替换日期
正式结果；最后仍须执行独立 `--validate`。不能拿历史表通过验证当作本轮成功。
