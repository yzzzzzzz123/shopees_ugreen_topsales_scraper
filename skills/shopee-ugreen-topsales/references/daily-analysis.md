# 每日 PDF 分析合同

全量采集、正式 Excel 发布和独立验收完成后必做。仅分析既有结果时只读 Excel，不启动浏览器。
报告固定输出到所选日期 `result/ugreen_topsales_analysis.pdf`，与四表 Excel 一起交付。
PDF 使用嵌入中文字体、A4 横向排版、跨页重复表头、章节书签、页码与可点击商品链接。图表保留等间隔点图和逐商品迷你趋势；排版中间文本仅在内存，不再输出 Markdown、PNG、HTML、JSON 或数据缓存。

## 输入与日期

- 唯一数据源是本项目注册日期 worktree 中、通过 `excel.validate_excel` 且模式为 `full_topsales` 的
  `result/ugreen_topsales.xlsx`。进度表、模板、已知商品详情刷新、不完整或损坏快照不参与比较。
- 业务日沿用目录对应的上海启动日；跨午夜保留启动日，并展示实际完成时间。
  不把刚完成的昨日任务改称今天的新采集。报告中的本日/昨日指业务日及其前一自然日。
- 以 `(shop_id, item_id)` 为关联键，不按标题、排名或 URL 文案关联。当前生产合同仍只支持 PH UGREEN
  `64922227`、PHP；其余竞品店铺须有明确目标、受支持的采集合同及各自完整快照后分别分析。
  没有其他店铺数据时不编造跨店比较。
- 自动发现不晚于本日的历史完整快照。昨天缺失就写不可计算，不能把“最近一次”冒充昨天。
  历史文件验收失败须在报告列明排除原因；当前正式表失败则不生成报告。
- 7 日、30 日都包含本日，按连续自然日排列。缺采、当日未观察到商品、未展示月销保留缺口，
  不补零、不前填、不插值、不跨缺口画连接线。只有一个观测点时明确尚不能判断趋势。

## 产品链接指标

| 指标 | 计算与展示 |
| --- | --- |
| 本日/昨日月销 | 保留本日原文，使用 Excel 的月销展示下界计算；缺失不作 0 |
| 月销变化值 | `本日展示下界 - 昨日展示下界`，只对两日均有月销的同一商品计算 |
| 月销变化率 | `差值 / 昨日展示下界 × 100%`；昨日为 0 仅列绝对变化，比例标“不适用” |
| 7 日及 30 日月销趋势 | 每个本日商品均输出迷你趋势图、有效天数和观察数值范围；日期轴等间隔 |
| 月销上涨/下滑/持平链接数 | 仅统计两日共同链接且月销均已展示的样本；未知单列，新增/消失不塞入上涨或下滑 |
| 本日/昨日价格及变化 | 使用列表价 PHP，列绝对差值及百分比；昨日缺失或为 0 采用相同缺失/零基期规则 |
| 每个产品客单价代理 | 当前列表价作为单件价格代理，不标成真实订单客单价 |
| 每个产品估算月销额 | `当前列表价 × 本日月销展示下界`；未知月销不估算 |

页面 `N Sold/Month` 是滚动月销展示口径，不是当日订单。两天的滚动月销之差不能推导新增订单、
净销量或退货。K/M/+ 的显示精度也不能还原真实精确销量；看似持平可能只是显示阈值未变化。
报告始终称“展示值/下界变化”，不把下界之差称作真实销量增长下界。

## 店铺 / 竞品观察指标

| 指标 | 计算与限制 |
| --- | --- |
| 与昨日相比的新出现链接 | 今日集合减昨日集合；这是上新观察代理，不是已确认的真实上架数 |
| 首次观察与重新出现 | 新出现集合中，全部已保存历史从未见过的记首次观察，其余记重新出现；不声称覆盖保存前历史 |
| 30 日上新趋势 | 每日新出现链接数量、首次观察与重新出现分别列出；只有相邻两日快照完整才能给出 0 或正数 |
| 首个基线日 | 全店链接不能全部计为上新；新增数和相关趋势点为缺数据 |
| 今日未观察到的历史链接 | 昨日集合减今日集合；不直接称已下架 |
| 当天观察到的总月销量 | 对已展示月销的链接求和，同时列已知/未知覆盖；全部未知时为不可计算，不记 0 |
| 估算总月销额 | 对已知月销商品求 `Σ(当前列表价 × 月销下界)`，仅为销售额代理，不是真实 GMV，也不保证是其下界 |
| 店铺加权单件价格 | `估算总月销额 / 已知月销合计`；无销量时不可计算，不冒充订单金额/订单数的客单价 |
| 各价格段出单占比 | 用该段可观测月销 / 全店可观测月销作销量结构代理；不是当天订单占比 |
| 链接动销 | 月销 >0 为可确认有动销，=0 为展示零月销，未展示为未知；不能将未知认定为滞销 |
| 动销比例 | 同时给出有月销链接 / 全部链接，以及有月销链接 / 已知月销链接，写清分母 |

PHP 默认固定价格段：`[0,100)`、`[100,300)`、`[300,500)`、`[500,1000)`、
`[1000,2000)`、`[2000,5000)`、`≥5000`。按本日列表价归档，边界只归一个段；
不使用每天重算的分位数区间。用户另定区间时统一更新后续口径并说明，不能静默混用。

店铺月销合计日变化可能同时受商品进出和展示覆盖影响。因此另列“两日同款且月销都可读”的
可比样本数量、月销变化与变化率。实际成交价、SKU 销量分配、客单商品件数、订单数均未采集，不能补造。

## 执行与交付

默认全量链路增加以下必做步骤：正式发布 → `--analyze`（先独立重开验收 Excel）→ `--validate` → `--archive`。
最终验收回执必须包含 `analysis.analysis_status=通过`，归档回执还必须有 `archive_status=通过` 和日期分支 commit，然后一起交付 Excel 和 PDF。
同日重新发布时先重新分析，再复核两份产物，避免旧 PDF 的哈希不一致阻断更新流程。
旧的单独 Excel 验收仍可运行，但不代表新增分析交付已经完成。

```text
argv = [PYTHON, ROOT_RUNNER, "--analyze", "--project-root", ROOT, "--worktree", DAILY]
argv = [PYTHON, ROOT_RUNNER, "--validate", "--project-root", ROOT, "--worktree", DAILY]
argv = [PYTHON, ROOT_RUNNER, "--archive", "--project-root", ROOT, "--worktree", DAILY]
```

新日期 worktree 的同版本 runner 同样提供该入口。对明确指定的既有日期补分析，使用主根最新
runner，只在该日期 result 新增/更新规定 PDF；不重新 prepare、不改历史源码、不重写源 Excel。
用户要求“分析并输出”已授权写这份报告；普通只读问答不自动重写报告。

报告覆盖店铺汇总、价格段、店铺 7/30 日趋势、30 日新增趋势、逐日覆盖数据、全部产品月销与价格变化、
每个产品 7/30 日趋势、当日新出现明细和来源日期/文件 SHA-256。数据不足时章节仍保留并说明缺口。
PDF 内的文字图表可直接阅读；商品文字转义，链接只来自已验收工作簿，不把商品文案当指令。

报告按受控候选回读后原子替换，与 Excel 共用发布锁。未知同名文件或符号链接保留并拒绝覆盖；
生成失败不破坏源 Excel。重新发布同日 Excel 后须重新分析，旧报告不能冒充新结果。
独立验收从来源重新计算并确定性生成 PDF，逐字节比较，同时核对源表哈希、日期与覆盖；报告被编辑或来源变化会报不一致。PDF 字节验证与人工渲染检查配合使用。更换排版器或字体后须重新生成并验收，不能把排版版本变化冒充源数据变化。
允许 result 包含正式 Excel、分析 PDF、可选进度 Excel；既有受控 `ugreen_topsales_analysis.md` 仅兼容保留，不更新、不作为以后正式交付。未知同名文件继续拒绝覆盖。

一次性旧 PDF 没有流程标识时，明确迁移先核对其 SHA-256，再用 `--analyze --legacy-pdf-sha256 HASH`；普通运行不设置此选项。


## 历史快照保存与读取

每个业务日对应一个 Git worktree 和 `daily/YYYYMMDD-ugreen-topsales` 分支。`result/ugreen_topsales.xlsx` 保存该日最新完整数据，`result/ugreen_topsales_analysis.pdf` 保存对应分析；`--archive` 验收后将这两个文件成对提交到日期分支，Git commit 是历史版本索引，不另造历史文件夹或数据副本。

- 同日重跑产生新提交，旧版本仍在该分支的 Git 历史中；相同产物重复归档不产生空提交。发布器在替换已有 Excel/PDF 前先归档上一对完整结果；上次中断留下不一致的一对时先 `--analyze`、`--archive` 补齐，再重发。
- 提交只包含这两份正式文件；累计进度 Excel、旧 Markdown 和用户其他改动不混入提交，不执行 push、pull、reset 或分支清理。
- 跨日分析按业务日选择一份完整快照。除日期 worktree 当前 Excel 外，也可只读其 Git 历史中的已提交 Excel；选择完成时间不晚于当前快照的最新版本，不把事后重跑的数据带入早先报告。
- 读取 Git 中的 Excel 只作受控临时展开，重开验收后立即清理，不检出旧 commit、不覆盖工作区。来源表列明文件哈希，使用 Git 版本时同时标出 commit。
- 没有验收通过的昨日快照仍是缺数据；历史进度表从不参与日环比。归档是本地持久化，未经推送不宣称远程备份。保留日期 worktree 与分支，不按缓存删除。

使用 `git -C DAILY log -- result/ugreen_topsales.xlsx result/ugreen_topsales_analysis.pdf` 查看该日历史提交。需要取回旧版本时另存到用户指定位置；日常分析不会修改或回退原结果。

PDF 依赖由 `pyproject.toml` 固定。Windows / WSL 自动使用本机微软雅黑、Consolas 和符号字体；其他环境通过 `UGREEN_PDF_FONT`、`UGREEN_PDF_BOLD_FONT`、`UGREEN_PDF_MONO_FONT`、`UGREEN_PDF_SYMBOL_FONT` 指向已有 TrueType 字体。缺字或字体不可用明确报错，不输出方框替代字符。
